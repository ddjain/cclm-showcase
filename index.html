Act 2 · Context

What is CCLM?

1
OpenShift Virtualization
Run VMs as pods on OpenShift — upstream is KubeVirt. VMs get all the Kubernetes advantages: scheduling, autoscaling, self-healing, monitoring — one platform for VMs and containers.
2
CCLM — a feature of OpenShift Virtualization
Cross-cluster live migration moves a running VM from one OpenShift cluster to another with no workload disruption — memory copied live over cross-cluster network, guest state preserved (same PIDs, no data gap), orchestrated by MTV/Forklift.
3
Where it's used
Keeping critical VMs online through infrastructure change — Tech Preview in OpenShift Virtualization 4.20.
cluster maintenance & evacuation hardware refreshes cluster consolidation regional workload mobility

Three ideas before the deep-dive: the platform, the feature, the reason it matters.

Act 5 · Customer recommendations

        
What customers should do

        

          
    
            
  • 1. Always verify VM health independently — do not trust Forklift status alone
    • 
            
  • 2. Patch target runStrategy back to Always after migration
    • 
            
  • 3. Monitor and clean orphaned target resources before retry
    • 
            
  • 4. Batch Plan creation (groups of 10, 30s gap) for 50+ VMs
    • 
            
  • Network: Protect br-migration first (<5% loss). <10 ms RTT low risk; >15 ms budget extra time
    • 
          

          

            
Known customer concurrency (awels): 5 VMs/cluster, 2/node. Our scale & chaos testing far exceeds that headroom.
